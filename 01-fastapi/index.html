Responses stream as they are produced

GET /stream returns a StreamingResponse that yields one line every 0.5 seconds. Python functions on Vercel send each chunk as soon as it is yielded, so the browser receives the lines one by one instead of all at the end.

One instance serves many requests

The app gives itself a random ID when an instance starts. Fluid compute keeps an instance warm and sends it more requests, so the same ID and a growing uptime mean no cold start. Requests sent at the same time may be spread across instances.

Type hints turn into validation

FastAPI reads the path, the query string and the JSON body from the function signature, converts them to the declared types, and answers 422 when they don't fit. Nothing about this changes on Vercel.

Endpoints and limits

Endpoints served by this app

POST /itemsA JSON body validated by a Pydantic model

GET /docsFastAPI's generated OpenAPI docs

A request can run for up to 300 seconds by default. Instance state, like the uptime above, lives only as long as the instance; keep anything durable in a database. On shutdown, the lifespan handler gets about 500 milliseconds to clean up.
