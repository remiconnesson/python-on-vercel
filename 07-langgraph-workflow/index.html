A LangGraph graph waits for your approval inside a durable Vercel Workflow

Give it a topic. The graph writes a short product blurb with an LLM, then stops at review until you approve the draft or ask for changes. That stop is a Workflow hook: the run is suspended with no function kept running, and it continues from the same point when you answer. Everything on this page comes from this deployment's API as you use it.

Waiting on a hook keeps no function running: until your answer queues the run again, it exists only as records in the Workflow event log. This page checks GET /api/runs/{id} about once a second while the graph works and every 3 seconds while it waits, so a time below can be up to one check late. Pause lengths are exact: the server measures each one from the moment the hook was created to the moment your answer resumed it.

The review node waits on a Workflow hook instead of an interrupt

Excerpts from agent.py. The model call is a durable step, the graph is ordinary LangGraph, and the whole graph runs inside one workflow.

Workflow makes each node durable, so the graph needs no checkpointer

The whole graph runs inside the body of a workflow function. Workflow writes every step result and hook answer to the run's event log, an append-only record of what happened. Each time the run wakes up, Workflow runs the body again from the top and answers every finished step and hook from that record, so LangGraph is back at the same node within milliseconds and the model is never called twice for the same draft.

How each part of the LangGraph graph maps onto Vercel Workflow
Graph partRuns asWhat Workflow does with it
graph.ainvoke()The body of @wf.workflow run_agentReplays it from the start on every wake-up, after a step finishes or a hook receives an answer
write nodeA call to generate(), a @wf.stepRuns the LLM call as its own invocation, retries it up to 3 times, and records the text it returns
review nodeApproval.wait(), a Workflow hook, instead of LangGraph's interrupt()Suspends the run; Approval(...).resume(token) records your answer and queues the run again
after_reviewAn async def conditional edgeEnds the graph when you approve, otherwise sends it back to write with your feedback
CheckpointerNoneThe event log is the persistence, so there is no database to set up; LangGraph's get_state() and time travel are not available

There is no official LangGraph integration for Vercel Workflow. This demo is a pattern built on the public SDKs of both, following the official example that runs another agent loop inside a workflow body.

Vercel deployed two functions from one pyproject.toml

The folder holds main.py, agent.py, pyproject.toml and uv.lock. There is no vercel.json and no environment variable to set.

The path of a run

  1. This browser

    Starts the run with POST /api/runs, checks it with GET, and answers with POST …/approve.

  2. Web function

    FastAPI in …, reached through …, records the start or your answer as an event, queues the run, and returns.

  3. Vercel Queues

    Deliver the run to the workflow function, and each step as its own message.

  4. Workflow function

    Replays run_agent from the event log, runs the graph to the next step or hook, records the result, and exits.

The region and edge location come from the x-vercel-id header of this page's last API response. The workflow function does not answer the browser, so its region is not shown.

Endpoints and limits

Endpoints served by this app
EndpointWhat it does
GET /This page for browsers, an endpoint listing as JSON for everything else
POST /api/runsStarts a run from {"topic": "..."} and returns its run_id
GET /api/runs/{run_id}The run's status, plus the draft, its number and the pause time while it waits, or the result once it completes
POST /api/runs/{run_id}/approveResumes the hook with {"approved": true} or {"approved": false, "feedback": "..."} and returns the pause length; 409 when the run is not waiting

The Python Workflow SDK is in beta. Every graph node and router is async def, because the workflow sandbox blocks the thread pool LangGraph uses for plain functions. LangChain is served to the sandbox from the regular interpreter through passthrough_modules, and step results are plain strings because Workflow can only record data it can serialize. Each wake-up replays every earlier node, so a long review loop does a little more work on every resume.
