A LangGraph agent runs inside one Vercel Function and streams each step as it happens

This page is served by the FastAPI app that runs the agent. The agent is a small graph: the agent node asks the model what to do, the tools node runs a multiply function when the model asks for it, and the loop ends when the model answers. The model is reached through AI Gateway with a short-lived token that Vercel issues to the deployment (OIDC), so no API key is stored.

The stream reports each node as it finishes, and the answer token by token

POST /stream runs the graph and answers with Server-Sent Events, a standard format for sending a series of events over one open HTTP response. A thread event comes first, then an update each time a node finishes and a token event for each piece of text the model writes. The page reads the response body itself, because the browser's EventSource only sends GET requests.

A follow-up on the same thread sees the earlier turn, as long as it reaches the same instance

The graph is compiled with InMemorySaver, which keeps each thread's messages in the memory of the instance that ran it. Send the thread_id back and LangGraph loads those messages before calling the model. Fluid compute usually sends the next request to the same warm instance, so this often works. A cold start, a redeploy, or a request that lands on another instance starts from an empty thread.

What Vercel did with this folder

The project contains main.py, index.html, pyproject.toml and uv.lock. There is no vercel.json and no stored secret; every decision below came from those files or from the platform.

A run can last up to 300 seconds by default; longer agent loops need a higher maxDuration. InMemorySaver never evicts threads, so memory grows with use; durable conversations need a Postgres checkpointer. The model has to support tool calls on the Chat Completions API. Credentials are checked before the stream starts, so a missing one returns a 500 with instructions instead of a broken stream; locally that means setting AI_GATEWAY_API_KEY or pulling VERCEL_OIDC_TOKEN.
